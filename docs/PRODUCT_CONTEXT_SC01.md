# SC01 产品背景与资产策略

状态：目标车型已确认，正式三维模型待重新获取。

## 产品定位

- 本系统服务于 `SC01` 的购车选配与方案沟通。
- 用户提供的项目背景表明，“江铃 羿驰”主要承担生产资质厂家和子品牌角色；面向消费者的产品主名称、页面标题和传播口径统一使用 `SC01`。
- 项目主理人为晓彤。该项目前仅作为内部协作背景，不在缺少公开授权资料时自动写入消费者界面。
- 公开报道显示 SC01 已上市；仓库仍以业务方最终提供的价格、配置、品牌和授权资料为发布依据，不以媒体文章替代产品主数据。

## 要解决的问题

SC01 的内饰和外饰定制程度高。当前缺少统一选配系统时，客户、销售和定制团队需要通过图片、聊天和人工表格反复确认方案，容易出现：

- 配置组合描述不一致。
- 内外饰效果难以快速比较。
- 价格与方案无法稳定复现。
- 客户确认结果难以跨销售、设计和生产环节传递。
- 高定制自由度放大沟通轮次，降低购车转化和交付效率。

因此产品优先级不是增加展示特效，而是建立唯一配置事实、快速对比、可复现方案、明确价格和跨端一致状态。

## 命名策略

| 层级 | 使用方式 |
|---|---|
| 消费者主名称 | `SC01` |
| 生产/资质信息 | `江铃 羿驰`，放在车型资料或合规字段，不作为主标题 |
| 技术 fixture | `demo-car`，仅保留给现有自动化和 `mvp-v1` 流水线验收 |
| 正式跨端 ID | 计划使用 `sc01`，通过新 catalog/publication 版本迁移 |

不得就地覆盖已经发布的 `mvp-v1/demo-car`。SC01 数据进入系统时应生成新的 catalog 与不可变 publication 版本。

## 模型时间线

用户曾收到团队提供的车辆模型，但本地文件已经丢失；预计约两周后团队复工时重新获取。

正式模型到位前：

- 允许继续使用程序化或许可明确的第三方代理资产开发系统能力。
- 所有代理资产必须标记为临时资源或隔离在 `_ImportStaging`。
- 公开图片只用于造型、镜头、分区和 UI 研究，不用于反向生成并冒充官方精确模型。
- 不发布标称为 SC01 最终效果的 64 图。

正式模型到位后：

1. 保留原始交付文件，不直接覆盖现有资产。
2. 通过管理员 FBX 模式校验授权、大小、SHA-256 和 sidecar。
3. 进入 `/Game/Configurator/_ImportStaging/<session>`。
4. 核对坐标、真实尺寸、节点、Pivot、材质槽、玻璃、灯、内饰、轮胎、碰撞和 LOD。
5. 验证车门、机盖、后备箱、轮胎和其他可动结构。
6. 在实时与 Path Tracing 下检查穿模、法线、玻璃、Bloom、构图和透明出图。
7. 建立 `vehicleId=sc01` 的正式 catalog，并发布新的不可变 Render 版本。
